# Kard

Bank card deals for Pakistan. Add your debit/credit cards, then browse discounts **daily, weekly or monthly**, filtered by **city** and **category**. Deals live in a Supabase database and are managed from an admin page.

> **The bundled deals are sample data, not live bank offers.** Replace them with real, verified offers via `/admin`.

No build step — it's a static site (HTML/CSS/JS). Cards a visitor adds are stored only in their browser (localStorage).

## Files

| File | Purpose |
| --- | --- |
| `index.html`, `app.js`, `styles.css` | Public app |
| `admin.html`, `admin.js`, `admin.css` | Admin page (`/admin`) — sign in, add/edit/duplicate/hide/delete deals |
| `catalog.js` | Banks, cities, categories (shared) |
| `sample-deals.js` | Built-in sample deals — offline fallback and seed source |
| `config.js` | Supabase URL + anon key |
| `supabase/schema.sql` | Table, constraints, row-level security, admin function |
| `supabase/seed.sql` | Optional: loads the sample deals (generated by `node scripts/build-seed.js`) |

## Set up Supabase

1. Create a project at supabase.com.
2. **SQL Editor** → run `supabase/schema.sql`, then (optionally) `supabase/seed.sql`.
3. **Authentication → Users → Add user** (email + password, auto-confirm) — this is your admin login.
4. Make that user an admin (SQL Editor):
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'you@example.com'
   on conflict do nothing;
   ```
5. **Authentication → Sign In / Providers** → turn **off** "Allow new users to sign up".
6. **Project Settings → API** → copy the Project URL and the `anon` key into `config.js`.
   Never put the `service_role` key in this repo or in the browser.
7. Deploy, then visit `/admin`.

If `config.js` is empty or the database is unreachable, the public app falls back to the built-in sample deals and says so.

## How access works

* Anyone can **read** deals where `active = true` (public site).
* Only signed-in users listed in `public.admins` can insert/update/delete, enforced by Postgres row-level security — not by hiding the admin page.
* The anon key in `config.js` is meant to be public.

## Run locally

Open `index.html`, or serve the folder: `npx serve .`
